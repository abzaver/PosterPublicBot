# Требования: PosterPublicBot

## Контекст и акторы

**ОК** — основной публичный канал, куда постятся картинки для аудитории.  
**АК** — административный чат (группа), где общаются админы ОК.  
**Бот** — находится в обоих чатах одновременно.  
**Админ** — участник АК с правом голосовать и публиковать.  
**Владелец** — человек, который зарегистрировал пару АК→ОК (workspace). Может быть один из админов.  
**Workspace** — логическая единица: одна пара АК→ОК со своим конфигом. Один экземпляр бота обслуживает несколько workspace одновременно.

## Сценарии использования

### UC-1: Детектор баяна

Когда кто-то из АК постит картинку (или GIF/видео), бот:
1. Вычисляет perceptual hash нового изображения.
2. Ищет похожие (Hamming distance ≤ порог) среди всех сохранённых из ОК и АК.
3. Если нашёл — отвечает реплаем: «Баян! Видел здесь: [ссылки на сообщения]».
4. Независимо от результата поиска — сохраняет хэш нового изображения в БД.

**Бот также следит за ОК**: каждое новое фото в ОК автоматически добавляется в БД (без уведомлений).

**Правило похожести**: два изображения считаются одним, если их pHash Hamming distance ≤ настраиваемого порога (по умолчанию 10).

---

### UC-2: Голосование и публикация в ОК

Когда кто-то из АК постит картинку:
1. Бот начинает отслеживать реакции на это сообщение.
2. Админы ставят реакции (положительные / отрицательные — настраиваемые списки).
3. Когда число положительных реакций достигает порога (настраиваемого):
   - Бот прикрепляет к сообщению inline-кнопку **[ОТПРАВИТЬ В ОК]**.
4. Любой из админов нажимает кнопку:
   - Бот пересылает изображение в ОК.
   - Кнопка становится неактивной / заменяется на «✅ Опубликовано».
5. *(Опционально)* Режим автопубликации: при достижении порога бот публикует сам, без нажатия кнопки.

**Правило голосования**: учитываются только реакции участников АК (не анонимные).

---

### UC-4: Онбординг нового workspace

Новый владелец канала подключает бота самостоятельно через личный чат:

1. Владелец находит бота и пишет `/start` в личку.
2. Бот создаёт черновик workspace, привязанный к `owner_user_id`, и выдаёт пошаговую инструкцию:
   - Добавить бота в АК (группу) и выполнить там `/set_ak`
   - Добавить бота в ОК (канал) как администратора
   - Вернуться в личку и выполнить `/set_ok @channel`
3. После выполнения обоих шагов workspace активируется.
4. Бот подтверждает готовность и предлагает просмотреть конфигурацию по умолчанию (`/config`).

**Правила:**
- Один владелец может создать несколько workspace (разные пары АК→ОК).
- Каждый workspace полностью изолирован: своя БД записей, свой конфиг, свои реакции.
- Поиск баянов происходит только внутри своего workspace.
- Онбординг через личку бота; в будущем возможен веб-интерфейс или суперадминка — архитектура это позволяет.

---

### UC-3: Конфигурация бота

Настройки хранятся в БД и меняются командами в АК.

| Параметр | Команда | По умолчанию |
|---|---|---|
| Зарегистрировать ОК | `/set_ok @channel` | — |
| Зарегистрировать АК | `/set_ak` (в нужном чате) | — |
| Порог похожести (Hamming) | `/set_hash_threshold N` | 10 |
| Положительные реакции | `/set_positive_reactions 👍 ❤️ 🔥` | 👍 ❤️ 🔥 |
| Отрицательные реакции | `/set_negative_reactions 👎 💩` | 👎 💩 |
| Порог голосов для публикации | `/set_vote_threshold N` | 3 |
| Автопубликация | `/set_autopublish on\|off` | off |
| Поведение при баяне | `/set_baян_action warn\|block\|warn_no_vote` | warn |

## Ограничения и правила

- Бот реагирует на фото, GIF, видео и текст через `/mem` (не на произвольный текст).
- В АК бот — единственный постер: все сообщения перепощивает от своего имени, оригиналы удаляет.
- Повторное нажатие «ОТПРАВИТЬ» не должно дублировать публикацию.
- При рестарте бота состояние кнопок должно восстанавливаться из БД.
- Только участники АК могут управлять конфигурацией своего workspace.
- Все данные (хэши, тексты, голоса, конфиг) изолированы по workspace_id.

---

## Нефункциональные требования

- Бот работает в режиме polling (текущий деплой на ECS).
- SQLite как хранилище; при необходимости масштабирования — миграция на PostgreSQL.
- Конкурентные запросы на обработку изображений не должны конфликтовать (временные файлы).
